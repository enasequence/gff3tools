# Summary

A written GFF3 document carries its translations in a single `##FASTA` section after the last
annotation, holding the translations of the annotations that document contains and no others.
Translations are taken from the first source that actually supplies any — the `TranslationState`
populated during validation, then an explicitly supplied translation FASTA, then translations
read back out of a source GFF3.

This replaces an arrangement in which `GFF3File` chose between writing a `##FASTA` section per
annotation and writing one at the end, and in which the choice of translation source was made by
asking whether a source object existed rather than whether it held anything.

# Motivation & Rationale

## Problems with the previous design

1. **A per-annotation `##FASTA` section produced invalid GFF3.** The specification makes
   `##FASTA` terminate the feature section: everything after it is sequence data to end of file.
   A document holding more than one annotation therefore had feature lines after its first
   `##FASTA`, and gff3tools' own reader — which stops at that directive — read such a document
   back as a single annotation, silently. The mode was written for one `GFF3File` per annotation,
   where the output is well formed; nothing prevented or warned about the multi-annotation use.

2. **Source selection tested presence, not content.** `TranslationState` is supplied by an
   auto-discovered provider, so it is never null. Selecting the first non-null source therefore
   always selected it, and when it happened to be empty — as it is on any path where no
   translation was generated or captured — the section was skipped and the remaining sources were
   never consulted. The documented fallback to an explicitly supplied translation FASTA could not
   fire at all.

3. **Translations were not scoped to the document.** Whichever source was used, a document
   received every translation the source held, whether or not the corresponding annotation was in
   that document.

4. **Accessions were matched by string prefix.** Translations are keyed `accession|featureId`, and
   an annotation selected its own by prefix, so `AB123.1` also claimed the translations of
   `AB123.10`.

## Rationale for the chosen approach

There is one correct place for a `##FASTA` section, so the writer no longer offers a choice about
where to put it; what a caller can still say is whether the document carries translations at all.
Choosing the source by content rather than by existence makes the fallback order meaningful and
matches the two-step idiom (`contains(...)` **and** a usable value) that `TranslationFix` and
`CdsTranslationPresenceValidation` already use for auto-registered providers. Scoping to the
document's own annotations makes a document self-consistent: its FASTA section describes its
feature section, whether it holds one annotation or all of them.

# Usage Guidelines

**Getting translations into a written document.** Supply a source and opt in:

```java
GFF3File.builder()
        .header(header)
        .species(species)
        .annotations(annotations)
        .translationState(translationState)   // or .fastaFilePath(...) / .gff3Reader(...)
        .writeAnnotationFasta(true)           // defaults to false
        .build()
        .writeGFF3String(writer);
```

`writeAnnotationFasta` defaults to `false`, so a caller that supplies a translation source but
does not opt in gets a features-only document. Both factory methods of `GFF3FileFactory` set it
for you: `from` always writes translations, and `fromAnnotationAndReader` takes the caller's
choice. That parameter is the only way to ask `fromAnnotationAndReader` for a features-only
document, because it always supplies a `TranslationState` from the reader's validation context.

**Source order.** First source that yields a translation wins:

| Order | Source | Typically |
|---|---|---|
| 1 | `translationState` | generated by `TranslationFix`, or captured from a flat file's `/translation` |
| 2 | `fastaFilePath` | an explicitly supplied translation FASTA |
| 3 | `gff3Reader` | translations read back out of a source GFF3's own `##FASTA` |

An empty source falls through to the next. If none supplies anything, no `##FASTA` directive is
written — an empty section is never emitted.

**Scoping.** A document carries the translations of the annotations it holds. Give it a subset of
a submission's annotations and it carries exactly that subset's translations. The one exception
is `fastaFilePath`, which is copied verbatim and cannot be filtered — do not combine it with a
document holding only some of a submission's annotations.

**Accession matching is exact**, version suffix included. An annotation recorded without its
version matches no translations rather than matching every version of that accession: a missing
translation is a visible failure, a misattributed one is not.

# System Overview / High-Level Design

`GFF3File.writeGFF3String` emits:

```
##gff-version …        header, when set
##species …            when set
…features…             every annotation, in order
##FASTA                once, only when a source yields translations
>accession|featureId   scoped to this document's annotations
```

Three collaborators supply translations. `TranslationState` (`validation/provider`) is the shared
state `TranslationFix` records into during validation. `GFF3TranslationReader`, behind
`GFF3FileReader`, indexes a source GFF3's `##FASTA` section by byte offset so protein sequences
are read one at a time rather than held in memory. `TranslationKey` owns the `accession|featureId`
key format and, now, its inverse.

# Detailed Design & Implementation

## Writing the section

`writeGFF3String` writes every annotation's features, then calls the source chain once. Each
source writer reports whether it emitted anything, so an empty source falls through instead of
ending the chain, and the `##FASTA` directive is written only by a source that has something to
follow it with.

## Scoping

The document's accessions are collected once per write, and both filterable sources are reduced
to translations belonging to them. Membership is decided by `TranslationKey`:

```java
public static String accessionOf(String key);                       // before the first '|'
public static boolean belongsTo(String key, String accession);      // exact match
```

Splitting on the first separator is safe: an accession never contains `|`, and feature IDs are
URL-encoded by `TranslationKey.of` (`|` → `%7C`). Keeping both the key format and its inverse in
one class is deliberate — the prefix defect above existed because two places decided the same
question independently.

## Offset lookup

`GFF3FileReader` buckets its translation offset map by accession on first use and caches it for
the reader's life, so an annotation's translations are a map lookup rather than a scan of the
whole map. This matters when one reader writes several documents: the file is parsed and indexed
once regardless of how many documents come out of it. Buckets preserve the offset map's sorted
order, so output is byte-stable across runs and consumers can rely on a checksum.

## Key design decisions

- **`writeAnnotationFasta` is retained.** Removing it was considered: the chain now writes nothing
  when no source supplies anything, so "no translations" can also be expressed by supplying no
  source. That does not hold for `fromAnnotationAndReader`, which always supplies a
  `TranslationState` from the reader's context, so the flag is the only way to ask that factory
  for a features-only document. It is also public API with consumers outside this repository.
- **The default stays `false`.** Opt-in rather than opt-out, at the cost that a caller who
  supplies a source and forgets the flag gets no translations.
- **The offset source stays last.** It reads a submitter's own `##FASTA` rather than anything
  gff3tools generated, so a populated `TranslationState` takes precedence wherever the two could
  disagree. The offset map itself remains the primary source for GFF3 → EMBL conversion, where
  `GFF3Mapper` turns those translations into `/translation` qualifiers.

# Alternatives Considered

**A concatenated multi-document format** — each annotation written as a standalone document,
separated by a repeated `##gff-version` header. Rejected: `##gff-version` mid-file is not valid
GFF3 either, so consumers would need a bespoke parser and gff3tools' own reader would still stop
at the first `##FASTA`. Every shape needed is expressible as an ordinary valid GFF3 document.

**Keeping the per-annotation mode, documented as multi-document output.** Rejected: it preserves a
way to produce invalid output for a use case that a separate document per annotation already
serves.

# Technical Debt / Future Considerations

- **`fastaFilePath` cannot be scoped.** It is an opaque file, copied verbatim. If a partial
  document ever needs it, that source needs an index.
- **No reverse-mapping validation.** `CDS_TRANSLATION_PRESENCE` checks that every CDS has a
  translation; nothing checks that every translation belongs to an annotation present in the
  document. `DUPLICATE_SEQ_ID` guarantees accessions are unique but says nothing about one being
  a prefix of another.
- **A submitted `##FASTA` is used silently or ignored silently**, depending on whether a higher
  priority source supplies anything. Callers that intend to ignore submitted translations get no
  diagnostic saying so.
- **`GFF3FileFactory.from` takes `##species` from the first entry only**, discarding later
  organisms without a diagnostic — a file-level directive forces a choice, but the discarding is
  invisible.
- **Streaming.** A single trailing section needs the annotation set up front. Offsets keep memory
  at one translation at a time, but a streaming writer would need two passes or a temporary file;
  `2604071325` already lists this as future work.

# Testing Strategy

`Gff3FileWritingTest` covers the writing contract, organised by the properties a written document
must satisfy: it is valid GFF3, it round-trips, and its `##FASTA` matches its own annotations.
Both factory methods are covered, along with the source chain's fallthrough, the empty-source
case, and exact accession matching at reader and writer level.

Two tests there are characterisations rather than requirements, labelled as such: that `from`
stamps the specification version regardless of the source, and that it takes `##species` from the
first entry only.

Run with `./gradlew test`.
